# probot_description

## Purpose

`probot_description` is the canonical robot model package. It defines the Probot kinematic chain, links, joints, and sensor placements used by MoveIt, `robot_state_publisher`, Gazebo, and hardware control.

## System architecture

- This package contains the robot model definitions in URDF/XACRO form.
- It exposes variants for standard use and for ROS 2 control (`probot.ros2_control.xacro`).
- It includes Gazebo-specific sensor placement and visual geometry in the `probot_anno_macro.xacro` file.
- It provides launch helpers for broadcasting the description.

## Key contents

- `urdf/probot_anno.xacro` - main robot description macro
- `urdf/probot.ros2_control.xacro` - ros2_control-compatible variant that injects the `ProbotSystemHardware` plugin
- `urdf/probot_isaac.urdf` - autogenerated Isaac Sim-compatible variant
- `urdf/gripper_macro.xacro` - gripper and end-effector macro definitions
- `launch/publish_robot_description.launch.py` - publishes `robot_description` and joint state GUI
- `launch/rviz_launch.launch.py` - visualization launch for the URDF
- `urdf.rviz` - RViz scene configuration for the model

## Frame conventions

- The robot tree begins at `world` and connects into `robot_base` via `world_to_robot_base`.
- The fixed chain goes `world` → `robot_base` → `base_footprint` → `base_link`.
- Arm joints are `joint_1` through `joint_6`.
- The end-effector/tool frame is exposed through `tool0`.
- Camera links are exposed as `camera_link1`, `camera_link2`, `camera_link3`.
- The Kinect sensor in Gazebo is attached at `camera_link2` and uses `/camera/depth/camera_info` and `/camera/depth/image_raw` in the bridged simulation path.

## Communication graph and coupling

- The URDF/XACRO output is consumed by:
  - `robot_state_publisher`
  - `move_group`
  - `ros2_control_node`
  - Gazebo entity spawn
  - RViz visualization
- `probot.ros2_control.xacro` contains a plugin block referencing `probot_hardware/ProbotSystemHardware`.
- Joint names defined here are implicitly coupled to `moveit_config` and `probot_hardware`.

## Hidden coupling points

- Joint names in this package must match:
  - MoveIt planning groups
  - `ros2_controllers.yaml`
  - `ProbotSystemHardware` state/command interfaces
  - Gazebo bridge and controller topics
- The `robot_state_publisher` launch in `probot_bringup` relies on the XACRO output still providing `robot_description` with the expected frame chain.
- The `tool0` and camera link names are used by higher-level perception and targeting pipelines.

## Behavioral constraints

- Do not change joint naming, frame hierarchy, or end-effector link names without updating all dependent packages and launch files.
- Preserve the fixed transform from `world` to `robot_base` and `base_link` to avoid breaking planning and visualization.
- Keep the `probot.ros2_control.xacro` hardware plugin block aligned with the plugin name and joint interface type expected by `probot_hardware`.
- Avoid changing camera frame names used by the vision stack unless the remappings in `gazebo_bringup.launch.py` are updated in lockstep.

## Performance assumptions

- The robot model is assumed to be a correctly formed URDF/XACRO with inertial and joint limit data where needed for MoveIt.
- The model is expected to support both simulation and hardware modes via XACRO parameters.
- Sensor placements and camera frames must remain semantically stable for perception and planning to interpret pose data correctly.

## Useful details for AI context

- This package is the source of truth for the physical model of the Probot arm.
- It bridges the abstract planning and perception stacks with the physical robot representation.
- It is where geometry, joint limits, and hardware plugin wiring are defined.
